# 海拾阿那亚代购地 — 产品设计规格

**日期：** 2026-08-29  
**状态：** 已确认（方案 A）  
**产品名：** 海拾阿那亚代购地  

## 1. 背景与目标

打造阿那亚场景下的代购小程序：用户浏览商品与代购费用，通过留资或联系客服完成代购意向；运营方在管理端维护品类、种类、商品明细与代购费用规则。

**一期不做**在线支付、购物车结算、完整电商订单履约。后续可升级为「代购集合店」（方案 C）。

参考（仅借鉴交互骨架，不复制业务）：

- 食研社：分类货架、采购提醒、公告
- 航忆小肚兜：清晰的集合店货架浏览

## 2. 产品定位

> **海拾阿那亚代购地** = 阿那亚代购商品橱窗 + 费用透明说明 + 一键联系/留资代购。

用户心智：来这里看阿那亚能代购什么、花多少服务费、何时采购，然后留下需求或加微信。

## 3. 范围

### 3.1 一期（In Scope）

**用户端（微信小程序）**

- 首页：品牌、公告、下次采购/截单时间、本期推荐、代购说明入口
- 分类：一级品类 + 二级种类 + 商品列表
- 商品详情：图文、规格、费用拆分、我想代购、复制/联系客服
- 我的：客服入口、我的询价记录、关于我们
- 微信登录：进入小程序即静默 `wx.login` 换取 openid；**提交「我想代购」前必须已拿到 openid**（未登录成功则提示重试，不允许匿名留资）

**管理端（Web）**

- 品类 / 种类 CRUD、排序、启停
- 商品 CRUD：图文、规格、上下架、归属分类
- 代购费用规则：按件 / 按比例 / 品类默认，商品可覆盖
- 采购日历：采购日、截单文案（驱动首页展示）
- 询价单：列表、状态变更、备注
- 基础配置：公告、客服微信号/企微链接、代购须知文案

### 3.2 明确不做（Out of Scope · 一期）

- 购物车、结算页、微信支付
- 正式履约订单流（待发货/物流单号等）
- 积分、充值、优惠券、会员等级
- 多货源店切换（山姆/盒马式）
- 团长/分销
- 复杂售后工单

## 4. 用户端信息架构

### 4.1 底栏（3 Tab）

| Tab | 职责 |
|-----|------|
| 首页 | 品牌与运营信息、采购提醒、推荐 |
| 分类 | 逛货主路径 |
| 我的 | 客服、询价记录、说明 |

### 4.2 首页模块（按序）

1. 品牌区：海拾 · 阿那亚代购地  
2. 公告条（可进入公告详情或富文本）  
3. 采购提醒：下次采购日、截单时间文案  
4. 本期推荐：运营勾选的少量商品（建议 ≤ 10）  
5. 入口：代购须知  

不堆砌营销卡片；首屏保持单一「代购集合橱窗」认知。

### 4.3 分类页

- 左侧：一级品类列表（仅启用）  
- 顶部：当前品类下的二级种类（含「全部」）  
- 右侧：商品列表卡片  

商品卡片字段：主图、名称、展示价摘要、仅「上架」商品展示。

**列表「展示价摘要」公式（qty=1，写死规则避免歧义）：**

- 主展示：`参考价 + 代购服务费` 的合计，文案形如 `约 ¥XX`（XX 为元，保留两位）  
- 辅行（小字）：`参考价 ¥A · 服务费 ¥B`  
- 无费用规则时：主展示仍为参考价，辅行写 `服务费详询客服`  
- 列表不做运费估算

### 4.4 商品详情

- 主图（可多图）、名称、规格说明、详情富文本/图文  
- **费用拆分区（必显，按 qty=1 计算展示）**  
  - 商品参考价  
  - 代购服务费（按规则计算结果 + 规则说明一句）  
  - 运费说明（配置文案，一期可不自动计价）  
  - 费用合计说明（参考价 + 服务费；注明运费另计或见说明）  
  - 用户在表单中填写的数量**不回写**详情页费用区；数量仅写入询价单，沟通时由运营按数量重算  
- 主 CTA：**我想代购** → 打开留资表单  
- 次 CTA：**复制客服微信** / **打开企微**（以后台配置为准）

### 4.5 留资表单（Lead）

字段：

| 字段 | 必填 | 说明 |
|------|------|------|
| 联系人姓名 | 是 | |
| 手机号 | 是 | 格式校验 |
| 微信号 | 否 | |
| 数量 | 是 | 默认 1，正整数 |
| 备注 | 否 | 规格偏好、收货城市等 |
| 关联商品 | 系统 | 从详情带入 productId |

提交成功提示：预计联系时效（可配置文案，默认「将在 24 小时内联系您」）。

提交时：云函数使用当前 openid 写入 `leads`；若无 openid，前端拦截并提示「登录后才能提交」。

### 4.6 我的

- 头像昵称（微信授权）  
- 我的询价：列表 + 简单状态  
- 客服：复制微信 / 企微  
- 代购须知、关于我们  

### 4.7 询价状态（用户可见）

| 状态 | 含义 |
|------|------|
| 新询价 | 刚提交 |
| 已沟通 | 运营已联系 |
| 已成交 | 代购达成 |
| 已关闭 | 取消或无效 |

用户端只读；仅管理端可改状态。

## 5. 管理端设计

### 5.1 品类（Category）

- 名称、图标（可选）、排序、启用/停用  
- 停用后前台不展示；其下种类与商品仍保留数据  

### 5.2 种类（SubCategory）

- 所属品类、名称、排序、启用/停用  
- **前台规则：** 停用种类不出现在顶部种类条；其下商品在该品类「全部」中**仍展示**（只要商品本身上架且所属一级品类启用）。停用品类则整棵子树前台不可见（见 5.1）。  

### 5.3 商品（Product）

- 名称、主图、图集、规格文案、详情  
- 所属品类（必填）、种类（**必填**；每个商品必须挂一个启用或停用的种类，不允许「仅品类、无种类」）  
- `categoryId` 必须与所选种类的父品类一致（管理端保存时校验或由种类自动带出品类，禁止错挂）  
- 参考价（分，整数存储）  
- 是否本期推荐、排序  
- 上架 / 下架  
- 费用规则：使用品类默认 **或** 商品覆盖规则  

### 5.4 代购费用规则（FeeRule）

支持类型：

1. **按件固定**：`serviceFeeFen = fixedAmountFen × qty`  
2. **按比例**：`serviceFeeFen = round(referencePriceFen × rateBps / 10000 × qty)`  
   - `rateBps` 用整数基点存储：`1000` = 10.00%（即万分比）  
   - `round` 为四舍五入到整数分  

作用域：

- 品类默认规则（每个启用品类至多一条默认）  
- 商品覆盖规则（有则优先于品类默认）  

前台必须展示计算后的服务费金额，并附简短说明（如「代购服务费 ¥5/件」或「代购服务费 10%」）。

若商品与品类均无规则：列表/详情服务费按「详询客服」处理（列表辅行文案见 4.3；详情服务费行显示「详询客服」，合计主数字仅含参考价，并注明服务费另询）。

### 5.5 采购日历（PurchaseBatch / Config）

一期可用配置项即可：

- `nextPurchaseDate`：下次采购日  
- `cutoffText`：截单说明文案  
- 首页「采购提醒」读取上述配置  

（后续可扩展为多期采购批次。）

### 5.6 询价单（Lead）管理

- 筛选：状态、商品、时间  
- 查看表单内容与关联商品快照（名称、参考价、当时服务费）  
- 改状态、内部备注  
- 不要求一期导出，可后续加  

### 5.7 系统配置

- 公告标题与内容  
- 客服微信号、企微链接（可选）  
- 代购须知、运费说明、留资成功提示文案  
- **关于我们**正文（「我的」页入口读取此配置，不硬编码）  

### 5.8 管理员引导

- 首次部署通过云开发控制台/初始化脚本写入首个 `admins` 记录（账号 + 密码哈希）  
- 一期不提供自助注册管理员  

## 6. 关键用户流程

```text
用户打开小程序
  → 看首页采购提醒 / 推荐
  → 进分类选品 或 点推荐进详情
  → 查看费用拆分
  →「我想代购」提交留资
     或「复制客服微信」私聊
运营在后台
  → 维护品类/种类/商品/费用/采购日
  → 处理询价单（沟通 → 成交/关闭）
```

## 7. 技术架构

| 层 | 选型 | 说明 |
|----|------|------|
| 用户端 | 微信原生小程序 | 与微信登录、分享一致 |
| 管理端 | Web，**默认 Vue 3 + 简单 UI 库** | 桌面操作为主，需可移动端浏览器使用；实现阶段不切换栈除非阻塞 |
| 后端 | 微信云开发 | 云函数 + 文档型数据库 + 云存储 |
| 鉴权 | 用户 openid；管理员账号+云函数校验 | 管理写操作全部走云函数 |
| 支付 | 无 | 一期明确不接入 |

### 7.1 核心数据集合（逻辑模型）

- `categories`  
- `sub_categories`  
- `products`  
- `fee_rules`（或内嵌于 category/product；实现阶段二选一，推荐独立集合便于审计）  
- `leads`  
- `configs`（公告、客服、采购日等键值）  
- `admins`（管理员账号哈希）  

商品列表、详情对 C 端只读；写操作仅管理员云函数。

### 7.2 安全

- 数据库安全规则：C 端不可直接写 `products` / `fee_rules` / `configs`  
- `leads`：创建时云函数强制写入当前用户 openid；用户仅可读自己的记录；状态变更仅管理员云函数  
- 无 openid 不得创建 lead（与 3.1 一致）  
- 管理端接口校验 admin token / session  

## 8. 非功能要求

- 商品图走云存储 CDN；列表页控制体积  
- 分类页滚动加载或分页，避免一次拉全库  
- 留资接口防刷：同 openid 短时间频率限制（如 1 分钟 1 次）  
- 文案与价格展示人民币，金额以「分」存储、「元」展示  

## 9. 分期与升级路径

| 阶段 | 内容 |
|------|------|
| 一期（本文） | 橱窗 + 费用 + 留资 + 管理后台 |
| 二期（方案 C 方向） | 购物车、正式订单、可选微信支付、订阅消息 |
| 三期 | 多货源、会员营销、数据看板 |

一期交付验收标准：

1. 管理端可完成品类→种类→商品→费用→上架全流程  
2. 用户端可浏览并看到正确的费用拆分  
3. 留资成功写入后台且状态可流转  
4. 首页采购提醒与公告可配置生效  

## 10. 决策记录

| 决策 | 选择 | 原因 |
|------|------|------|
| 产品形态 | 方案 A 橱窗+留资 | 用户确认；最快验证供需 |
| 底栏 | 3 Tab | 无购物车则无需第 4 Tab |
| 费用 | 必须拆分展示 | 代购信任核心 |
| 后端 | 云开发 | 空项目、小团队、无独立运维 |
| 多货源 | 不做 | YAGNI |
| 在线支付 | 不做 | 方案 A 边界 |
